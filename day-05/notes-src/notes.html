Ethereum & the EVM

Learning objectives

  1. Explain the two kinds of Ethereum account (EOA and contract) and what a nonce does.
  2. Read EVM bytecode as a list of opcodes and trace what each one does to the stack.
  3. Work out the gas of a transaction: the 21,000 base cost, cheap opcodes, expensive storage, cold vs warm access and refunds.
  4. Find any Solidity variable in raw storage: packed slots, mappings at keccak256(key, slot), arrays at keccak256(slot) + i.
  5. Prove a model is right by testing it against the real thing (differential testing).

The concept, step by step

Step 1 — From a coin ledger to a world computer

Days 01–04 built a ledger that only tracks who owns how many coins. Ethereum keeps that ledger and also runs programs on it. Every node runs the same small computer, the EVM (Ethereum Virtual Machine), on the same inputs, and every node must get exactly the same result. If one node got a different answer, the network would split.

Step 2 — Two kinds of account

Externally owned account (EOA)Contract account
Controlled byA private key (a person or a bot, Day 03)Its own code
Has code?NoYes, fixed once deployed
Has storage?NoYes, 2256 slots of 32 bytes
Balance + nonceYes: nonce = transactions sentYes: nonce = contracts it created
Starts a transaction?YesNo, only reacts to calls

The nonce is a counter. Each transaction must use the next number, so the same signed transaction can never be played twice. A contract's address is also worked out from its creator and nonce: keccak256(rlp(sender, nonce)). In my run the predicted and real address matched exactly.

Step 3 — The EVM is a calculator with a stack

Contract code is a list of one-byte instructions called opcodes (0x01 = ADD, 0x55 = SSTORE). Each opcode takes numbers off the top of a stack of 256-bit numbers and puts its answer back on top. Here is "store 2 + 3 in slot 0":

Figure 1 — The stack after each opcode. Top of the stack is highlighted. Total execution gas: 3+3+3+3+22,100.

Step 4 — Gas: the price list that keeps the computer alive

Every opcode costs gas. You pay gas used × gas price. Gas does two jobs: endless loops stop because they run out of gas, and spam costs real money because thousands of nodes repeat your work. A plain ETH transfer always costs exactly 21,000 gas.

The biggest costs are in storage, because every node must keep that data for ever. The first time a transaction touches a slot it is cold (2,100 extra); after that it is warm (100), from EIP-2929.

SSTORE write (cold slot)GasWhy
0 → x (new value)22,100A new 32-byte value every node must keep
x → y (change)5,000The slot already exists
x → x (no change)2,200You only pay for the access
x → 0 (clear)5,000 − 4,800 refundFreeing state is rewarded (EIP-3529: refund ≤ ⅕ of gas used)

Step 5 — Storage: a wall of lockers

A contract has 2256 lockers (slots) of 32 bytes, all zero until written. Solidity fills them in the order variables are declared and packs small values into one slot when they fit. Mappings and dynamic arrays cannot be stored in order (they can grow without limit), so their items are placed at keccak256 addresses where they will never collide.

Figure 2 — Real storage of Layout.sol read with eth_getStorageAt. Packed values share a slot; mappings and arrays are scattered by keccak256.

3. Finding a variable in storage (src/storage.js)

// balances[key] when the mapping is declared at `slot`
function mappingSlot(keyType, key, slot) {
  return BigInt(keccak256(coder.encode([keyType, "uint256"], [key, slot])));
}
// items[i] when the array is declared at `slot`: keccak256(slot) + i
function arraySlot(slot, index) {
  const start = BigInt(keccak256(zeroPadValue(toBeHex(slot), 32)));
  return (start + BigInt(index)) % (1n << 256n);
}
// read a packed field: shift right by its offset, keep `size` bytes
function unpack(word, offset, size) {
  return (getBigInt(word) >> BigInt(8 * offset)) & ((1n << BigInt(8 * size)) - 1n);
}

4. The contract that shows the layout (contracts/Layout.sol)

uint256 public counter;               // slot 0

Common mistakes

  • Thinking gas price = gas. Gas measures work; the price per unit changes with demand. Fee = gas used × gas price.
  • Forgetting the first write is expensive. Setting a slot from 0 costs 22,100; designs that create many new slots get costly fast.
  • Reordering variables in an upgradeable contract. The slot numbers move and old data is read as the wrong thing (Day 11).
  • Trusting a model you never compared with reality. My unit tests passed; only the differential test caught D1.
  • Using transfer to send ETH. Its 2,300-gas limit breaks smart-contract wallets; use call and check the result.

Interview questions

1. Why does the EVM need gas at all?
Without it a single loop could freeze every node for ever. Gas makes every step cost something, so loops end and people pay for the work they ask the network to do.

2. Where does Solidity store balances[alice] if the mapping is declared at slot 3?
At keccak256(abi.encode(alice, 3)). Slot 3 itself stays empty.

3. Why does the second increment() cost less than the first?
The first changes the slot from zero (a new value, 20,000 + cold 2,100); the second only changes an existing value (2,900 + cold 2,100).

4. What is the difference between an EOA and a contract account?
An EOA is controlled by a private key and can start transactions; a contract account is controlled by its code, has storage, and only runs when called.

5. How can you be sure a home-made EVM is correct?
Differential testing: run the same random programs on it and on a reference EVM, and require identical gas at every step, the same storage and the same output.
